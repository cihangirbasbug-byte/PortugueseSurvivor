# Portuguese Survivor — Sprint Guide

## 1. Purpose

This document defines how Portuguese Survivor work is planned, executed, reviewed, tested, and completed.

The sprint system exists to:

- maintain focus
- reduce scope drift
- organize AI agents
- make progress measurable
- protect MVP priorities
- prevent unfinished work from accumulating
- ensure completed work is tested
- create a repeatable production process

---

# 2. Sprint Definition

A sprint is a short, focused production period with:

- a clear objective
- a limited scope
- defined tasks
- assigned owners
- measurable outcomes
- a completion criteria

A sprint is not simply a list of ideas.

Every sprint must have a specific goal.

---

# 3. Sprint Objective

Every sprint begins with one primary objective.

Example:

> Complete and validate the first playable mission.

A good sprint objective should be:

- clear
- measurable
- achievable
- aligned with the roadmap
- relevant to the current project phase

Avoid objectives such as:

> Improve the game.

Instead:

> Implement and validate Mission 01 including gameplay, Portuguese content, rewards, and completion flow.

---

# 4. Sprint Duration

Recommended sprint duration:

### Early Development

1 week

### Stable Production

1–2 weeks

### Major Production Phase

Up to 2 weeks

Avoid unnecessarily long sprints.

Shorter cycles make problems visible earlier.

---

# 5. Sprint Planning

Before starting a sprint:

1. Review roadmap.
2. Review unresolved P0/P1 issues.
3. Review previous sprint.
4. Identify the highest-value objective.
5. Define sprint goal.
6. Define deliverables.
7. Assign owners.
8. Identify dependencies.
9. Identify risks.
10. Define Definition of Done.

---

# 6. Sprint Priority

Use:

### P0

Critical blockers.

Must be addressed immediately.

### P1

High-impact issues.

Should normally be addressed before new features.

### P2

Important improvements.

Can be scheduled within the sprint when capacity exists.

### P3

Optional improvements.

Normally remain in the backlog.
